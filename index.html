4Check it: SHACL validation

SHACL is the standard way to write rules for a graph, like a building code review. Here are three rules for FCU-6F-10. Press the button to test the graph against them.

    See the three rules written in SHACL 
    # Rule 1: every fan coil unit has a return air temperature point
ex:R1-FCU-RAT  a sh:NodeShape ;
  sh:targetClass  brick:FCU ;
  sh:property [
    sh:path  brick:hasPoint ;
    sh:qualifiedValueShape  [ sh:class brick:Return_Air_Temperature_Sensor ] ;
    sh:qualifiedMinCount  1 ;
    sh:message  "FCU lacks a return air temperature point" ] .

# Rule 2: every fan coil unit is installed somewhere
ex:R2-FCU-Room  a sh:NodeShape ;
  sh:targetClass  brick:FCU ;
  sh:property [
    sh:path  rec:locatedIn ;
    sh:minCount  1 ;
    sh:message  "Equipment has no installed location" ] .

# Rule 3: the zone it supplies contains its room
ex:R3-FCU-ZoneRoom  a sh:NodeShape ;
  sh:targetClass  brick:FCU ;
  sh:sparql [
    sh:message  "Supplied zone does not contain the installed room" ;
    sh:select  """
      SELECT $this WHERE {
        $this brick:feeds ?zone ; rec:locatedIn ?room .
        FILTER NOT EXISTS { ?zone brick:hasPart ?room }
      }""" ] .

    Example shapes for learning. In the real project these run in pySHACL with the Brick 1.4.4 ontology. This page runs the same three checks in JavaScript, so you can try them without installing anything.

    6Passing is not proof

    Rules check that facts fit together, not that they match the building. Record FCU-6F-10 in the wrong room and the wrong room’s zone, then check again.
